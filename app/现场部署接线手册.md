# 现场部署接线手册

> 人工标准化操作监测系统（VisionForge）
> 适用：HC-500-10GM 千兆网工业相机 + 光电硬件触发 + 三色灯声光报警
> 版本：v1.0.0 · 2026-09-11

---

## 0. 先读这个（5 分钟看懂整套系统）

这套系统做一件事：**光电触发拍一张图 → 视觉判断零件/工具是否到位 → 合格放行下一道工序，不合格锁线 + 亮灯 + 蜂鸣 + 存图留证。**

它分三层，部署时按顺序来：

| 层 | 干什么 | 谁负责 |
|---|---|---|
| 硬件层 | 相机、光电传感器、光源、PLC、三色灯 | 电气工程师 |
| 算法层 | Halcon 视觉检测（零件/工具双 ROI） | 视觉工程师 |
| 软件层 | C# 上位机（SOP 状态机 + 界面 + 报警 + 历史） | 本系统 |

**关键设计**：上位机通过「配方」和「SOP 定义」驱动，换产品/换工位**不用改程序**，改配置即可。

## 2. 硬件接线

### 2.1 相机网络

- HC-500-10GM 是 GigE 相机，用**千兆网线**直连工控机网卡（或经千兆交换机）。
- 工控机网卡 IP 设成与相机同网段，例如：
  - 工控机：`192.168.1.100 / 255.255.255.0`
  - 相机：`192.168.1.101`（用 MstarViewer 配）
- **强烈建议相机走独立网卡**，不要和生产网共用，避免带宽被抢导致丢帧。

### 2.2 光电传感器 → 相机触发（硬触发核心）

光电传感器接到**相机广濑 12Pin IO 接头的 Line0 输入脚**：

```
光电传感器（NPN）输出 ──→ 相机 Line0 输入引脚
光电传感器电源         ──→ DC24V（相机 IO 需外部供电）
GND                    ──→ 共地
```

触发逻辑：**人手/工件离开检测区域 → 光电导通 → Line0 收到上升沿 → 相机拍一张。**

- 优先选 **NPN 型**光电（信号低电平有效，跟相机 IO 电平更好匹配）。
- 触发边沿：**上升沿 RisingEdge**（物体离开时信号由低变高）。

### 2.3 三色灯 + 蜂鸣器 → PLC 输出

软件默认的 PLC 地址映射（可在 `config/appsettings.json` 里改）：

| 信号 | PLC 地址 | 说明 |
|---|---|---|
| LightGreen | M110 | 绿灯：正常 |
| LightYellow | M111 | 黄灯：警示（不停线） |
| LightRed | M112 | 红灯：故障（停线） |
| Buzzer | M113 | 蜂鸣器 |

PLC 的 M110~M113 输出点接到三色灯和蜂鸣器的控制继电器（PLC 输出点一般带不动灯和蜂鸣器，需经中间继电器）。

### 2.4 上位机 → PLC 通讯

软件默认走 **Modbus TCP**（端口 502）：

- PLC 的以太网口接工控机（可与相机同交换机）。
- 在 `config/appsettings.json` 里改 `Plc.IpAddress` / `Port` / `Brand`。
- 如果 PLC 走三菱 MC 协议 / 西门子 S7，需在硬件抽象层新增实现类（见第 6 节）。

## 3. 相机参数配置（MstarViewer，必须先做）

> ⚠️ 这步不做，相机不响应触发，系统永远"等待触发"。

1. 打开 **MstarViewer**，连接相机。
2. 设置以下参数：

| 参数 | 值 |
|---|---|
| TriggerMode（触发模式） | **Hardware / On（硬件触发）** |
| TriggerSource（触发源） | **Line0** |
| TriggerActivation（触发极性） | **RisingEdge（上升沿）** |
| ExposureTime（曝光） | 30000 μs 起步，按光源亮度调 |
| Gain（增益） | 按需（黑白全局快门一般 0~10dB） |

3. **保存参数到相机非易失内存**（断电不丢）。
4. 关闭 MstarViewer（**Halcon/上位机要独占相机，两个程序不能同时连**）。

## 4. 软件部署

### 4.1 安装 .NET 8 Desktop Runtime

本发布包是**框架依赖**版本，工控机需先装运行时（一次性）：

1. 下载 **.NET 8 Desktop Runtime (Windows x64)**：
   https://dotnet.microsoft.com/download/dotnet/8.0
   （选 **Desktop Runtime**，不是 SDK，也不是 ASP.NET Core Runtime）
2. 安装，下一步到底。
3. 验证：命令行输入 `dotnet --list-runtimes`，能看到 `Microsoft.WindowsDesktop.App 8.x` 即成功。

### 4.2 拷贝程序

把整个发布目录（`publish/win-x64/`）拷到工控机，例如 `D:\VisionForge\`。

目录结构：

```
D:\VisionForge\
├─ VisionForge.Main.exe       ← 主程序
├─ VisionForge.Main.dll
├─ VisionForge.Common.dll
├─ VisionForge.Core.dll
├─ VisionForge.Hardware.dll
├─ VisionForge.Infrastructure.dll
├─ *.json / *.pdb             ← 配置 + 调试符号（可删 pdb）
├─ config\
│  └─ appsettings.json        ← 全局配置（相机/PLC/报警）
└─ data\                      ← 运行自动生成（配方/历史/NG图/日志）
   ├─ recipes\*.json          ← 检测配方
   ├─ sop.json                ← SOP 步骤定义
   ├─ history\                ← 检测历史（JSONL 按天）
   ├─ ng-images\              ← NG 取证图
   └─ logs\                   ← 日志
```

### 4.3 首次启动（先用 Mock 验证，不接硬件）

第一次部署，**强烈建议先用模拟模式把界面和流程跑通，再切真实硬件**：

1. 双击 `VisionForge.Main.exe`。
2. 默认配置里相机是 `Mock`、PLC 是 `Mock`——界面直接能看，点「启动监测」跑通全流程。
3. 确认界面、SOP 步骤、报警灯、历史表格都正常后，再切真实硬件。

### 4.4 切换真实硬件

编辑 `config/appsettings.json`：

```jsonc
{
  "Cameras": [
    {
      "Id": "CAM-001",
      "DisplayName": "工位1 · HC-500-10GM",
      "Vendor": "GigE",              // Mock 改成 GigE（或对应的相机厂商）
      "Model": "HC-500-10GM",
      "SerialNumber": "相机序列号"
    }
  ],
  "Plc": {
    "Brand": "ModbusTcp",           // Mock 改成 ModbusTcp
    "IpAddress": "192.168.1.10",
    "Port": 502
  }
}
```

保存后重启程序。

## 5. ROI 标定（现场不用改 JSON，鼠标画框）

1. 主界面左下角点 **「🎯 标定 ROI」** 进入标定模式（光标变十字，画面顶部出现提示条）。
2. **按住左键拖拽**画出检测框（松开即生成，自动命名"区域N"，颜色按顺序分配）。
3. **右键点击已有框**删除该框。
4. 画完点 **「✅ 完成标定」**，再点 **「保存配方」** 生效。

> 对 SOP 序列检测，**ROI 画框顺序 = 工序顺序**：第一个框 = 第 1 步，第二个框 = 第 2 步，以此类推。

## 6. 配方与 SOP 配置

### 6.1 检测配方（`data/recipes/*.json`）

一个配方 = 一个检测点（相机参数 + 算法 + ROI + 阈值）。界面「新建配方」或直接改 JSON 都行。

### 6.2 SOP 定义（`data/sop.json`）

一个 SOP = 一个产品的步骤序列，每步引用一个配方。示例：

```json
{
  "Name": "洗地机主机装配 SOP",
  "ProductModel": "WM-XXX",
  "Steps": [
    { "Seq": 1, "Id": "S1", "Name": "取件并放入工装", "RecipeId": "配方ID", "BlockNextOnFail": true },
    { "Seq": 2, "Id": "S2", "Name": "安装电机",       "RecipeId": "配方ID", "BlockNextOnFail": true }
  ]
}
```

- `BlockNextOnFail = true`：本步 NG 锁线，必须返工合格才能进下一步。
- `BlockNextOnFail = false`：NG 只告警不放行拦截（辅助工序用，避免频繁锁线）。

## 7. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 一直"等待触发" | 相机没配硬触发，或光电没接 Line0 | 检查 MstarViewer 触发设置 + 光电接线 + 边沿极性 |
| 相机连接失败 | 网段不通 / 相机被 MstarViewer 占用 | 查网卡 IP；关闭 MstarViewer 独占 |
| 拍照全黑/全白 | 曝光或增益不对 | MstarViewer 调曝光/增益，存到相机 |
| 检测框位置错 | ROI 是上个机位标的 | 重新标定 ROI（第 5 节） |
| 蜂鸣器一直响 | 自动消音没生效 / 报警没复位 | 点「消音」；检查 `Alarm.BuzzerAutoOffSeconds` |
| 历史里中文乱码 | 用记事本打开了无 BOM 的 CSV | 用 Excel/WPS 打开（导出已带 BOM） |
| 程序打不开 | 没装 .NET 8 Desktop Runtime | 装运行时（第 4.1 节） |

## 8. 关于"自包含"发布（可选）

当前交付的是**框架依赖**版本（需装 .NET 8 Desktop Runtime，体积小、升级方便）。

如果要**自包含**（目标机不用装运行时、整个包拷过去就能跑），在**能联网的开发机**上执行：

```bash
dotnet publish src/VisionForge.Main -c Release -r win-x64 --self-contained true -o publish/win-x64-sc
```

> 说明：自包含需要从 NuGet 下载 runtime pack，本项目的开发沙箱环境限制了 restore，所以改在能联网的机器上跑上面这条命令即可，产出的 `publish/win-x64-sc/` 整个目录拷到工控机就能直接双击运行。
